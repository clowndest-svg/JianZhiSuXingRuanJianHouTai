## 2. 环境变量（名字按实测，不要凭印象改）

Directus 认的是 `DB_*`/`KEY`/`SECRET` 这套扁平名，不是 `DIRECTUS_` 前缀（K-2/K-16 实测可用）：

| 变量 | 实测值/来源 | 说明 |
| --- | --- | --- |

| `PUBLIC_URL` | `https://124.220.54.64`（**不要**带 /admin） | 带路径会被再叠一层，得出 `<base href="/admin/admin/">`，整站资源 404（实测） |

## 3. 运维 API 的端点（两层身份：HTTP Basic + 运维令牌）

监听 `172.17.0.1:8100`（K-19：nginx 在另一个容器里，够不到本机回环），由 nginx 反代到 `/ops/*`。

- **L2 外层闸**：所有请求（含 `/api/login`）都要 HTTP Basic。口令没配好时返回 **503**，
  宁可拒服也不静默敞开。实现是 `basic_gate_middleware`，常数时间比对，可被单测直接打到。
- **L3 应用层**：运维令牌放 **`X-Qingsu-Token`** 头（不是 `Authorization: Bearer`——
  那一格被 Basic 占了，两个方案不能共用同一个头），或 `POST /api/login` 换来的
  `Secure; HttpOnly; SameSite=Strict` 会话 cookie（8 小时）。
- 明文 http 上 cookie 会被客户端丢掉（这正是 Secure 该有的行为），所以脚本用令牌头、浏览器用 cookie。

| 方法 | 路径 | 作用 | 防呆 |
| --- | --- | --- | --- |
| POST | `/api/login` | 令牌换会话 cookie | 同 IP 8 次错令牌锁 15 分钟；失败也落审计 |
| POST | `/api/logout` | 清 cookie | — |
| GET | `/api/whoami` | 当前身份（console/script） | — |
| GET | `/api/health` | 聚合 `/health/ready` + 容器状态 + 磁盘内存 + 备份列表 + 密钥是否被重建 | 只读 |
| GET | `/api/overview` | 看板数字（**全部现算**，含 K-12 里 Directus 读不到的那 12 张表） | 只读，拿不到主应用就明写 `unreachable` |
| GET | `/api/users` | 按 id/用户名/昵称/轻塑号找人（运维页要先"找得到人"才谈得上封号） | 只出白名单列；limit 上限 50 |
| GET | `/api/users/{id}` | 用户详情 + 各表条数 + 最后会话时间 | 只出白名单列 |
| GET | `/api/users/{id}/export` | 单用户数据包 | 只导出该用户自己的行 |
| GET | `/api/audit` | 最近 N 条审计（前后值已解析成对象） | 敏感列再脱敏一遍 |
| POST | `/api/users/{id}/ban` | 封号 | body 要 `expect_username` 完全匹配 |
| POST | `/api/users/{id}/unban` | 解封 | 同上 |
| POST | `/api/users/{id}/revoke-sessions` | 撤销全部会话 | 返回删了几条 |
| POST | `/api/users/{id}/reset-password` | 重置为一次性密码 | 响应里给新密码，**同时撤销全部会话** |
| POST | `/api/users/{id}/delete-account` | 注销（级联删） | body 要 `expect_username` + `confirm_rows`（服务端算出的行数，必须回显一致） |
| GET | `/api/gate` | 当前 `min_build`、各 build 客户端计数 | 只读 |
| POST | `/api/gate` | 抬门 | body 要 `expect_current` 且 `new >= current`；只升不降 |
| POST | `/api/brake` | 拉刹车（门写 0，放开全部客户端） | body 必须原样带回确认短语“放开全部客户端” |
| POST | `/api/backup` | 触发备份 | 跑完必须回读 `integrity_check` 才算成功 |
| GET | `/` | 运维页（单文件，不引外部 CDN） | 同样在 Basic 后面 |

### 3.1 三条实现硬要求

**① 高危动作的"回显确认"不是 UI 弹窗，是服务端比对。**
`delete-account` 的 `confirm_rows` 由服务端先算一次（走 FK 自省枚举，
复用主应用 `scripts/purge-users.py` 已验证的那套，含 `PRAGMA defer_foreign_keys`
和"提交失败整笔回滚"），调用方必须把这个数带回来。对不上就 409 拒绝。
这样"看错人"和"重放点击"都失败得下来。

**② 抬门只许升不许降。**
```python
if new < current: raise 400("门只能往上抬，往下放要走人工确认流程")
```
降门等于把旧客户端放回线上，风险不对称，不给按钮。刹车（`set-min-build.py off`）要在页面上明写。

**③ 每个动作写一行 `admin_audit`，含前后值。**
失败也要写（`after_json` 记错误），否则排查时只看到"什么都没发生"。

### 3.2 Directus 侧的两条使用约束（实测带来的，不遵守就会"看着像坏了"）

- **权限行的 `fields` 必须是逗号分隔字符串**（K-9 实测）：写成 JSON 数组时 Directus 会当成
  “一个字段都不许读”，接口只回主键——看着像屏蔽生效，其实是后台读不出东西。
  读请求本身要显式带字段清单；权限里没列出的字段会被 **403** 明确拒绝。
  运维页与控制台列表都必须 `?fields=id,username,...`，字段清单由 `field_whitelist.py` 生成，
  不在 HTML 里手写。
- **写权限必须列出可写字段**（K-9）：`fields` 为空的 update 权限直接 403
  （实测报 `You don't have permission to access fields "status", "reply"`）。
- **K-12 那 12 张无单列整数主键的表不在控制台挂链接**，一律从 `/api/overview` 出数。

## 4. 主应用侧改动（C-1 / C-2 / C-4）

改动落在主仓库，**不在本仓库**，但必须在这里写清，因为它有回归风险。

### C-1 封号

现役查询是 `server.py:842`：

```python
row = conn.execute("SELECT u.* FROM users u JOIN sessions s ON s.user_id=u.id "
                   "WHERE s.token_hash=? AND s.expires_at>?", ...)
```

要做的只有三件事：补列、在同一条语句的返回里多带两列、判一下。

```python
# migrate_db()
_ensure_columns(c, "users", [("banned_at", "TEXT"),
                             ("ban_reason", "TEXT NOT NULL DEFAULT ''")])

# get_current_user()  ← 关键：SELECT u.* 已经带上新列，不新增往返
if row["banned_at"]:
    raise HTTPException(403, "该账号已被停用：" + (row["ban_reason"] or "详见站内说明"))
```

**为什么强调"不加新往返"**：`get_current_user` 每个 `/api/` 请求都跑。
为后台给它加一次独立查询 = 全站每次请求多一次 DB 往返。这条有性能判据（测试 T-80）。

### C-2 运维 API 独立进程

不塞进 `server.py`（它已经 ~4400 行，见 03 §11 N-1），而是独立的 `ops/admin_api.py`，
直接读写同一个 SQLite 文件。理由：崩了不影响主应用、可单独重启、
权限边界清晰（主应用进程永远拿不到"抬门"这件事）。
代价是要处理并发写 → WAL + `busy_timeout=5000`，已由 K-5 实测成立。

### C-4 密钥挪出挂载目录

`server.py:3266`、`server.py:3450` 两处从 `DB_DIR` 取密钥路径，改成
`KEY_DIR = os.environ.get("QINGSU_KEY_DIR", DB_DIR)`；systemd 加一行
`Environment=QINGSU_KEY_DIR=/opt/qingsu/keys`（`700 qingsu:qingsu`），把两个旧文件 `mv` 过去。
**不设这个环境变量就等于不改**——这是它能安全回退的原因。

同时补诚实性：`media_key()` / `ws_secret()` 现在"文件不在就静默新建"，
要在真正新建时记一条 warning 并在 `/health/ready` 报 `keys_regenerated=true`（03 §9 F-4）。

### C-2b 数据目录权限

```
chmod 2770 /opt/qingsu/data      # setgid：容器新建的 -wal/-shm 自动落 group=qingsu（K-3）
chmod 660  /opt/qingsu/data/qingsu.db
```

执行前必须先确认没有第三个进程以 uid 1000 之外的身份写这个库；执行后立刻 `curl /health/ready`。

## 7. 代码风格与硬约束

1. **不打印秘密**。任何日志、异常、响应里不得出现 token、密码、hash。
   出错只报类型名（`type(e).__name__`），主应用已经是这么做的。
   测试输出里出现哈希要先脱敏再打印（本轮探针就是这么做的）。
2. **SQL 全参数化**。表名列名只能来自写死白名单或 `PRAGMA` 自省枚举，不拼用户输入。
3. **"读不到" ≠ "没有"**。聚合接口要区分这两种并带到界面文案（`kb_entries` 恒空、
   SMTP 未配、geoip 库缺失都必须各说各的话）。
4. **高危动作幂等或可判定**。封号重复调用返回当前状态而不是报错；
   抬门重复调用因 `expect_current` 不匹配而拒。
5. **改服务器配置前先备份**，改完必须独立回读验证（`nginx -T`、`sha256sum`、从公网 GET 一次），
   **不看部署日志的"成功"字样**。
6. **上传脚本到服务器后必须 `md5sum` 双向比对再执行**（本轮实测：`scp` 偶发返回 0 但文件没落盘，
   靠校验和才发现）。
